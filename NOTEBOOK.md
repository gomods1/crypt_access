## Decisions

- Keys (2026-11-23). Everywhere: F1 help, R repeat, Ctrl+arrows buffers. Playing: Space freeze, PageDown/PageUp scanner, Home repeat, Shift+PageDown/PageUp category, N route, U unexplored, B beacon, Shift+arrows review cursor, End cursor home, C surroundings, H/G/I/L/M HUD. Not used: W A S D (second keyboard layout), T (chat), P (multiplayer pause), Q/E (replays), Tab, punctuation (layout dependent).
- Speech interrupts on user-driven focus (menus, scanner, keys) and queues for events, per screen-reader convention.
- Positional cues use our own OGG earcons (tools/make_sounds.py) through system.game.Audio, not the game's sound groups.
- Translations: one Lua table per language (LangXX.lua), keyed by the game's language code; `tools/check_lang.py` must pass before a release.
- Shared Rust installer (user agreed 2026-11-23): C:\Users\Nitropc\code\mods\installer has an offline-only entry (GAMES[15], build_offline_cotn.bat, src/bin/cotn_offline.rs) using two new Game hooks: mod_root, and after_install/after_uninstall for the config.json patch. Tested in a sandbox with a fake LOCALAPPDATA: install, patch, uninstall, config restored exactly. Not committed (that repo also holds someone's uncommitted Rift work).
- Descriptions (2026-11-23): texts in `Desc<LANG>.lua`, one per language, looked up after `Lang<LANG>.lua`. English is generated by `tools/make_desc.py` from `tools/desc/desc_en.txt` (entity and scene texts) and `tools/desc/cutscenes_en.md` (per video: seconds and text); never edit DescEN.lua by hand. Texts were written from the game's own art (contact sheets: `tools/video_sheets.py`, `tools/portrait_sheets.py`) and entity data (AI type, components, spells). Entity keys are `desc.<EntityType>`; variants fall back through ALIAS, known suffixes (Dancer, Headless, Angry, PhaseN...) and trailing digits (Describe.keyFor). Translations were made by one agent per language using the game's CSV names; `tools/check_lang.py` checks Lang and Desc files.
- Four settings switch the descriptions: describe.cutscenes, describe.newEnemies, describe.combat, describe.scenes (all on by default). Each enemy kind is described on first sight once ever: hidden string setting describe.seen.
- Online play (user, 2026-11-23: "do the online multiplayer"): the packaged route, never a client-only hack (a mod hidden from the session's mod list would also hide it from the game's leaderboard checks). Build `CryptAccess-<version>.necromod` with `tools/build_package.py` (the game's packer through the dev console; reads dist\pkgstage, writes dist and mod\CryptAccess\package, never the game's mods folder). The zip ships it in CryptAccess\package; install.ps1 copies it to %LOCALAPPDATA%\NecroDancer\mods and removes other versions, and Package.lua does the same at every launch (for the Rust installer). Friends put the same file in their mods folder; without the config.json change the mod is silent on their machine. Every released version needs its own package build: bump mod.json whenever scripts change, or hashes differ between players. The Rust installer's uninstall leaves the copied package in the mods folder (its cotn_after_uninstall only removes the mod folder): to change, with a rebuild of the installer.
- Release: `tools/package.ps1` makes dist\CryptAccess-v<version>.zip with a PowerShell installer (install.bat/uninstall.bat). The DevConsole is excluded from releases.
- Release: `tools/release.ps1 -NotesFile notes.md` (user, 2026-11-23: a local script, no GitHub Action, because only the running game can build the .necromod). It checks the version is unreleased, git is clean and pushed, translations; starts the game and builds the package (build_package.py); closes the game; builds the zip (package.ps1); tests the zip with the online installer (`--cli`, redirected stdin, fake game folder and fake LOCALAPPDATA under %TEMP%\CryptAccessReleaseCheck, guarded so the real junction is never seen); publishes tag v<version> on main with the zip, the package and the installer exe from the previous release; then tests the install from GitHub. `-DryRun` stops before publishing; `-CheckOnly` re-tests the current version's zip and its GitHub release. The installer takes the first .zip of the latest non-prerelease release and refuses while Necrodancer.exe runs.
- Dev copy keeps the unpacked mod (user, 2026-11-23): Package.lua skips copying the bundled package into the mods folder when `dev\enabled` exists (never shipped). Proven: log "Mounting unpacked mod CryptAccess v0.3.1" and "Package: dev copy, package not installed", no 0.3.1 package in the mods folder.

- Speech goes in-process through LuaJIT ffi and `prism.dll`. No helper program and no proxy DLL. Reason: lowest latency and nothing extra to run.
- Mod install edits `Necrodancer64\config.json`: adds `core.StandardLibrary` to `wos.game.mods.scriptWhitelist` and `{"name":"CryptAccess"}` to `wos.game.mods.preload` (user agreed, 2026-11-23). The installer keeps a backup and re-applies the edit after Steam updates.
- The mod adds itself to the game's own mod list at load time (`ModList.lua`), because the game re-applies `modLoader.list` right after startup.
- Mod name and namespace `CryptAccess`. It is an unpacked mod in `%LOCALAPPDATA%\NecroDancer\mods\CryptAccess` (a junction to `mod\CryptAccess` in dev).

- The packer: `bridge.res.compiler.createPackage(realSourceDir, packageFile, relativeFileList)`, then poll getStatus (1 running, 2 complete, 3 failed), pollLogOutput, release. `bridge` is a global of system.mod.ModLoader, reached with getfenv(ModLoader.compile). Proven: built CryptAccess-0.3.0.necromod (67 files), 2026-11-23.
- Startup drops mod-list entries whose version is no longer installed (Mods.unloadInvalidVersions). The saved entry still said 0.1.0 on this machine, so the first launch after any update would unload Crypt Access; ModList.lua now rewrites the entry to the installed mod.json version at preload. Proven by log ("entry version 0.1.0 -> 0.3.0"), 2026-11-23. Anyone who updated from v0.1.0 to v0.2.0 hits the bug until 0.3.0 is out.
- Chat: every line (players' messages and the game's notices) goes through event.chatMessage (orders turn, replay, log, display, sound; ev.name, ev.text, ev.playerID, ev.turnID). Proven with chat.print and chat.addMessage, 2026-11-23. Spectating: necro.game.character.Spectator isActive, getTargetPlayerID. Host pause: StateControl.isPauseAllowed is false for clients.

## Pitfalls

- Editing Lua through a bash heredoc + Python turns a written backslash-n escape into a real line break, which breaks the Lua string (twice on 2026-11-24). Use the Edit tool for lines with escapes.
- Locals of a mod script must be declared above the handlers that use them; a later `local` is a global lookup inside the handler and errors every frame.
- A fresh save needs more than deleting saves: tutorial.pending, latency.calibration.pending, intro.seenVersion and seizureWarningDismissed live in SynchronyOptions.lua and the game copies them back into SynchronyUser_*.lua, so the first "clean" launch went straight to the lobby (proven 2026-11-23: removing those keys gave the seizure warning on the next launch). Decision (user, 2026-11-23): `tools/reset_save.ps1` wipes everything instead of single flags: all of %APPDATA%\NecroDancer and all of %LOCALAPPDATA%\NecroDancer except `mods` and `overlays`, backed up to %TEMP%\CryptAccessSaveBackup\<time>\Roaming and \Local. Tested on a fake folder only. HYPOTHESIS: the game's cloud sync (braincloud folder, settings with cloud = INIT) may bring some settings back; check after the first real full reset.
- The saved mod-list entry can say `package=true` (left over from package tests): the game then swaps the unpacked folder for the .necromod at startup ("Mounting packed mod CryptAccess"), the dev console is gone (dev\ is not packed) and script edits do nothing. A version bump fixes it (ModList rewrites the entry with package=false).

- The permission classifier refused (2026-11-23, session 4) opening the networkHost menu through the menu crawl, and writing the package into %LOCALAPPDATA%\NecroDancer\mods by hand (Package.install from the dev console). The mod makes that copy itself at the next launch.

- Saving a mod script while the game runs reloads the mod and restarts the current level; announcements of the level start come again. Translation agents saving files during a test doubled the boss splash lines (2026-11-23).

- 2026-11-23 incident: an installer unit test ran Crypt Access's uninstall against the real %LOCALAPPDATA% path, and through the dev junction it deleted mod\CryptAccess\scripts, sounds and mod.json (not in git). Recovered from dist\CryptAccess-v0.1.0.zip (built 08:10); DevConsole.lua (never in releases) was rewritten. The test now skips games with mod_root. Commit the project, and never let a test run a game whose mod_root is outside a temp folder.
- The decompiled `.lua` files have a UTF-8 BOM; grep still works.
- Jumping to deep levels with goToLevel counts as reaching them: on 2026-11-23 it unlocked Eli, Monk and Dove on the user's save. Buying in the lobby diamond shop unlocked the Spear (Lanza). A rebind test (real Left key through SendInput) stored "Key_1073741906" for Move left and in every combo that uses Left (UP_LEFT, DOWN_LEFT, ITEM_1, ITEM_2, BOMB); each was restored with `Controls.setKeyBind(1, "action", id, 1, "<default>")` (a full `resetToDefault` was refused by the permission classifier). Never finish a rebind test with SendInput keys; cancel it instead.
- Running a downloaded exe was blocked by the auto-mode classifier. Without auto mode it runs after a normal prompt.
- Killing the game with Stop-Process skips its settings save. To check persisted settings, quit the game normally.
- The first Mods-script read fails ("unloaded script necro.mod.Mods") during the preload mount. The second mount succeeds, so this is harmless.

## Dev tools

- `tools/launch.ps1 [-Restart]` starts the game (-Restart kills it with Stop-Process -Force; close it with CloseMainWindow first instead). `tools/shot.sh name` saves `shots/name_s.png`.
- `tools/dev.py "lua"` runs Lua in the game through `DevConsole.lua` (active only when `mod/CryptAccess/dev/enabled` exists): `R(name)` requires any module, `M.Name` a mod module, `key("enter","wait",...)` injects keys, `S(v)` serializes. `--speech N` prints the last spoken lines.
- `tools/SendKeys.ps1 -Keys UP,ESC` sends real OS keys (steals focus; prefer `key()`).
